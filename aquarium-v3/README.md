## 上課操作

1. 下載[四種魚著色紙](templates/aquarium-v3-a4.pdf)或[水母、魟魚、章魚著色紙](templates/aquarium-ocean-a4.pdf)。黑白、A4 橫式、原尺寸 100% 列印。保留整張紙，四角標記不要塗改。
2. 插上實物投影機。用 Chrome 或 Edge 的一般視窗開啟[教師掃描端](https://ff41009tw52-rgb.github.io/mimi-cream-farm/class-aquarium-v3-scan.html)，點「開始自動掃描」並允許攝影機。首次允許後會顯示裝置名稱，如畫面是筆電鏡頭，從下拉選單改選實物投影機。
3. 在 Windows 按 **Win+P → 延伸**。從掃描端點「開啟水族館」，把[展示視窗](https://ff41009tw52-rgb.github.io/mimi-cream-farm/class-aquarium-v3-display.html)拖到教室大螢幕後，點「全螢幕」。兩頁使用同一瀏覽器及同一個設定檔。
4. 一次平放一張著色紙，辨識成功就自動加入。看見「已上傳到水族館」後移開紙，等到「已就緒，可以放上下一張」再換紙，留出約兩秒空桌時間。淺色桌面上可鋪素色深底紙，並將鏡頭調到整張 A4 入鏡。
5. 角落遮蔽、模糊或反光時，先移開遮擋並重新放正。「拍照掃描」和「匯入照片」辨識成功也會直接加入。辨識不完整時，才會顯示修正畫面，可選魚種、將 1–4 對準紙上方格中心後預覽。
6. 手機開啟掃描端時會優先開後鏡頭。相機開啟後可切換前後鏡頭，也可用「用後鏡頭拍照」開系統相機，照片辨識成功就直接加入。同源同步仍以同一台裝置及瀏覽器設定檔為範圍。
7. 在展示端的「作品與設定」可逐張刪除、清空、切換低效能或減少動態效果。用完點掃描端的「停止攝影機」。作品保存在這個瀏覽器的網站資料中，清除網站資料也會刪除作品。

## V3 技術規格

| 項目 | 規格 |
| --- | --- |
| A4 紙張 | 297 × 210 mm，座標寬 800、高 565.6566；左上角為原點，四個標記中心依序為 (43,43)、(757,43)、(757,522.6566)、(43,522.6566)。 |
| 標記 | 每個標記 7 × 7 格，外圈黑框，內部 5 × 5 位元編碼。外框約 15.6 mm，標記與最近紙邊留約 8.2 mm。44 組碼連同旋轉版兩兩至少相差 8 位。四角共同辨識物種、角位和紙張版本，讀碼每角最多容許 2 位誤差。 |
| 選型 | 既有的實心黑方塊只能提供位置。單一 QR 還需要解出紙張的其餘位置。本版用四個 ArUco 類自訂標記，每角都提供位置、方向與魚種，以一致性檢查四角。辨識器為專案內的 JavaScript，執行時無 CDN 或第三方依賴。 |
| 自動校正 | Web Worker 掃描時約每 240 ms 處理影格，等待移開紙張時約每 370 ms 處理影格，分析影像最長邊 896 px，做局部灰階二值化、黑框連通元件定位、四角輪廓擬合與碼字驗證。用四個標記的 16 個角擬合平面投影，並檢查重投影誤差和魚身範圍。四角必須同屬一種魚且各有一個角位。 |
| 送件條件 | 魚形一致、即時掃描時三個影格的標記中心偏移最多 8 分析像素。魚區亮度取樣允許最多 20% 的點亮度差超過 32 階，以容許少量取樣點跨過墨線。寫入完成後鎖住。需要連續五個影格無有效碼、至少三組原標記框消失且魚區畫面已有變化，才接受下一張。 |
| 作品擷取 | 以相同影格的彩色資料作透視取樣，再依著色紙的外輪廓遮罩擷取。保留著色和筆畫，輸出透明 PNG。色彩會受相機曝光與白平衡影響。 |
| 同步 | IndexedDB 每張作品一筆，含 UUID、時間、魚種、PNG Blob。寫入交易完成後才發出 BroadcastChannel 通知，展示端收到後再讀取。沒有 BroadcastChannel 時以 storage 事件通知，展示端亦每 4 秒讀取一次補漏。 |
| 展示 | 可供 1920 × 1080 的教室螢幕全螢幕展示，分層繪製海底背景、光、漂浮粒子、氣泡、魚群和海草。魚群分七個深度位置上下浮動並在兩側慢慢轉向。低效能模式降低畫布解析度及更新次數，減少動態效果會停止游動。 |
| 資料 | 上限 80 份本機作品，同步設計以一個教師掃描視窗、一個或多個同源展示視窗為主。影像留在該瀏覽器，不收集姓名、班級或座號。 |

魚作品的像素只來自攝影機或匯入照片。海底背景為專案內的 WebP，執行時只讀靜態美術檔。

## 驗收門檻和重跑方式

| 項目 | 門檻 |
| --- | --- |
| 魚種 | 48 張四角完整、魚身可擷取的合成樣本，至少辨識對 95%。12 張空白或角碼缺失的樣本，誤收 0 張。 |
| 裁切 | 896 × 704 的合成影像中，魚區包圍盒與取樣點的投影誤差最大 3 px；每張擷取圖的四個外角 alpha 均為 0。 |
| 色彩 | 魚身四個點的每色道差值不超過 14/255，以攝影機影格的相應像素為基準。 |
| 同步 | 正常的 BroadcastChannel 路徑，從建立保存紀錄到另一頁 PNG 解碼可畫的時間不超過 500 ms。 |
| 魚群 | 1920 × 1080、40 尾看板展演，3.5 秒都可用於幀率量測，平均至少 30 FPS。 |
| 教室 USB | 四種紙各兩張，逐張自動收件 8/8，重複收件 0 張，等待就緒後換紙，展示端加魚無須重整。 |

以 Chromium 跑全流程的實測數字見[驗收紀錄](TEST-RESULTS.md)。同樣的程式可重跑：

- 到[瀏覽器合成影像測試頁](https://ff41009tw52-rgb.github.io/mimi-cream-farm/aquarium-v3/tests/browser.html)按「測試四種魚形」。此測試不需實物投影機，測試圖不進水族館。
- 在 repo 根目錄執行 `node aquarium-v3/tests/paper-gate.mjs`。安裝測試用 Sharp 後，可執行 `FIXTURES_DIR=./fixtures node aquarium-v3/tests/recognition.mjs`，同時輸出合成 JPG。設 `METRICS_PATH` 可以輸出逐圖數據。
- 以 `python3 -m http.server 8765` 起本機服務。安裝 Playwright 和 Chromium 後執行 `node aquarium-v3/tests/integration.mjs`。可用 `AQUARIUM_URL`、`CHROMIUM_PATH` 指定站點和 executable。以獨立測試瀏覽器設定檔執行，模擬攝影機的影格和斷線。
- 要重製模板，使用已整理的原圖與輪廓，先執行 `node aquarium-v3/tools/generate-templates.mjs`，再以裝有 Noto Sans CJK TC、Inkscape 和 Poppler 的環境執行 `sh aquarium-v3/tools/make-pdf.sh`。

### 教室實機驗收

1. 先由 Windows 用「相機」確認投影機可作影像裝置，測完關閉該程式，避免佔用鏡頭。如果 Chrome/Edge 找不到裝置，確認設備有 UVC 或相容的 webcam 驅動。
2. 四種模板各印兩張並以蠟筆、色鉛筆或彩色筆著色。每種一張正放，另一張略斜或沿桌面偏移。逐張記錄猜到的魚種、擷取有無越線及展示是否立即出現。
3. 第一張留下至少 5 秒要維持 1 隻。用手遮住一個角後拿開也維持 1 隻。取走第一張等到「已就緒」，再放下一張。
4. 關掉再開展示頁，對照作品數量。測試瀏覽器拒絕授權和掃描時拔掉 USB，確認提示與重試有效。
5. 以 Windows 延伸畫面投影，40 份作品全螢幕播放至少五分鐘。檢查教師切換掃描端時大螢幕是否持續播放，實際需要時開啟低效能模式。

## 手機和平板的下一階段

- **共用辨識**　沿用自訂標記、Web Worker 和 PNG 擷取。手機可用後鏡頭拍照，先在本機去背。保留排隊重送，以班級場次與作品 UUID 讓重試不重複收件。
- **角色與審核**　老師登入建立限時場次，學生掃 QR 取得場次限定、短效、僅可上傳的憑證。後端驗證檔案尺寸、格式和存取權。新作品進待審區，只有老師能讀取、核准或刪除，展示端只訂閱已核准作品。
- **Supabase**　以私有 Storage 放魚圖，Postgres 存 UUID、場次、狀態和期限，以 RLS 隔開班級和角色。核准後通知展示端以短效簽名 URL 載入。只讓指定的 HTTPS 起源向上傳入口發請求，服務端校驗憑證，不在前端放管理金鑰。成本依容量和傳輸計算，例如 40 張各 300 KB 約 12 MB，若有 10 台設備各完整載入一次約 120 MB 傳輸。實際配額以採用時的方案為準，並設定自動清除期限。參考 [Supabase Storage 權限文件](https://supabase.com/docs/guides/storage/security/access-control)。
- **Google Apps Script**　學校 Workspace 帳號可一併評估登入與網域限制。Drive 作品和權限由學校設定，用輪詢替代即時訂閱。需先實測 GitHub Pages 到 Web App 的登入重新導向、CORS 預檢、寫入併發和每日配額。參考 [Web Apps](https://developers.google.com/apps-script/guides/web)與[配額文件](https://developers.google.com/apps-script/guides/services/quotas)。
- **資料最小化**　上傳透明魚圖，不上傳含桌面、學生臉孔或姓名的原始相機影格。學校先決定誰能看、保存多久和如何刪除，再開放跨裝置活動。

## 版本與檔案

V3.1.2 放寬即時掃描的輕微晃動與墨線取樣波動容許量。

V3.1.1 即時掃描、拍照掃描、手機拍照和匯入照片辨識成功後都直接加入水族館並顯示「已上傳」。紙張辨識不完整時仍可手動修正。

V3.1.0 使用四張新插圖及與其對應的新標記。原本的 V3.0.0 著色紙可繼續掃描，手動對位時也能選「原版線稿」。手機優先開啟後鏡頭，完成儲存會跳出成功提示。

V3.0.0 包含四種 A4 自動定位模板、USB 自動掃描與備援、雙視窗同步、海洋展示和驗收工具。兩個網頁入口在 repo 根目錄。其餘內容位於 `aquarium-v3/`：

| 檔案 | 內容 |
| --- | --- |
| `class-aquarium-v3-scan.html`、`class-aquarium-v3-display.html` | 掃描／展示入口 |
| `templates/*.svg`、`templates/aquarium-v3-a4.pdf`、`templates.js` | A4 原稿、合併 PDF、尺寸、魚形、碼字 |
| `geometry.js`、`detect.js`、`extract.js`、`scan-worker.js` | 定位、辨識、透視擷取與 Worker |

| `collection.js` | IndexedDB 作品管理與同源通知 |
| `display.js`、`display.css`、`swim.js`、`assets/ocean.webp` | 展示、美術、魚群和動態設定 |
| `tools/`、`tests/`、`TEST-RESULTS.md` | 原圖輪廓處理、模板生成、合成影像和驗收 |
